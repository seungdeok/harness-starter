# 선택지를 하나 늘리면 "이전 상태"의 가짓수도 늘어난다 — 파생 결함 체인

- 날짜: 2026-08-05
- 작업/PR: [#39](https://github.com/seungdeok/harness-starter/pull/39) (이슈 [#38](https://github.com/seungdeok/harness-starter/issues/38)), 브랜치 `ISSUE-38`

## 문제

`/harness:setup` 의 `CLAUDE.md` 배치를 한 조각에서 두 조각(A=가이드라인 / B=문서참조)으로 나누고
조각별 scope 를 허용했다. 기능 자체는 단순한데, 리뷰에서 **결함이 세 번 연달아** 나왔다.
셋 다 계획서에 없었고, 앞의 것을 고치자 다음 것이 생겼다.

```
원안: "스캔 행 1개 유지" (재실행 확인 프롬프트를 1회로 지키려고)
  └─ F2  A 를 글로벌에 뒀는데 스캔이 프로젝트만 봐서 `없음` → 재실행마다 재-append
     └─ D10  행을 2개로 나누자, 레거시 harness:start 레포에서 둘 다 `없음`
              → 기존 블록 위에 새 블록이 덧붙어 가이드라인 2중 로드
        └─ D11  레거시를 막았어도, scope 를 바꿔 재실행하면(글로벌→프로젝트)
                 이전 위치를 안 봐서 A 가 두 곳에 남음
```

D10 은 사용자가 "하위호환은 되는거지?"라고 물어서 나왔다. 안 물었으면 그대로 나갔다.

## 원인

계획이 **"이번 실행"만 보고 설계됐다.** 선택지를 1개에서 2개로 늘리면 사용자가 도달할 수 있는
**이전 상태**는 1가지에서 여러 가지가 된다:

| | 이전 상태의 가짓수 |
| --- | --- |
| 조각 1개, 배치 1가지 | `설치됨` / `없음` — 2가지 |
| 조각 2개, 배치 2조합, 레거시 존재 | 조각별 위치 × 레거시 유무 × **이전 실행의 답변** — 10가지 넘음 |

판정 로직은 "지금 무엇을 설치할까"만 봤고, "**이전에 어디에 설치됐을 수 있나**"는 안 봤다.
그래서 결함이 전부 **재실행 경로**에만 나타났다 — 최초 설치는 세 번 다 멀쩡했다.

체인이 된 이유도 같다. F2 를 고치며 *판정 대상*을 늘렸더니 레거시라는 이전 상태가 드러났고(D10),
그걸 고치며 *판정 시점*을 늘렸더니 이전 답변이라는 상태가 드러났다(D11). 한 축을 볼 때마다
가려져 있던 다음 축이 나왔다.

## 해결

- **F2** — 스캔 마커 행을 2개로 분리. 조각이 다른 파일에 갈 수 있으면 한 행으로는 상태를 표현할 수 없다.
- **D10** — 레거시 마커 판정을 신규 행보다 **먼저** 두고, 위치별로 다르게 판정
  (프로젝트 레거시 = A+B, 글로벌 레거시 = A만 — 구본이 글로벌에선 B 를 제외했기 때문).
- **D11** — `guidelines` 는 이번 답변과 **무관하게 두 파일을 모두** 스캔. 다른 위치에 있으면
  `다름 (다른 위치에 설치됨)` 으로 알리고 `옮기기/양쪽 유지/그대로` 를 묻는다.

검증은 임시 레포 probe 10케이스(PASS=23). 결정적이었던 것은 **회귀 반증** — 구버전 로직을
같은 fixture 에 돌려 `없음` 이 나오는 것까지 찍었다. 통과만 봤으면 "고쳤다"와 "원래 문제가
없었다"를 구분 못 했다.

```
P4 (A글로벌+B프로젝트 재실행)   신규=다름            구본=없음  ← F2 가 고친 결함이 실재
P9 (글로벌→프로젝트로 답 변경)  신규=다름-다른위치   구본=없음  ← D11 이 고친 결함이 실재
```

## 재발 방지

**선택지·조합을 늘리는 변경은 "이 실행에서 무엇을 만드나"가 아니라 "사용자가 어떤 이전 상태에서
올 수 있나"를 전수로 세고 설계한다.** 늘어난 선택지 수보다 이전 상태의 가짓수가 훨씬 빨리 는다.

전수 세는 축 세 개 — 이번에 결함이 나온 자리와 정확히 같다:

1. **위치** — 산출물이 갈 수 있는 곳이 여럿이면, 판정도 그 전부를 봐야 한다
2. **구본** — 이전 버전이 남긴 형식이 있으면, 신규 판정보다 **먼저** 본다
3. **이전 답변** — 사용자가 지난번에 다르게 답했을 수 있다. 판정 대상을 이번 답변에 종속시키지 않는다

그리고 **최초 실행이 아니라 재실행 경로부터** 검증한다. 결함 셋 다 최초 실행에서는 안 보였다.

→ [GUARDRAILS.md](GUARDRAILS.md) 에 승격.

## 부수 확인 — 셸 cwd 가 남아서 검사가 전부 빗나갔다

구현 중 `cd skills/setup/templates && python3 ...` 을 한 번 쓴 뒤로 그 cwd 가 남아, 이후 상대경로
`grep -rn ... skills/` 가 전부 `No such file or directory` 로 조용히 빈 결과를 냈다. 덤으로 그
디렉토리에 `.omc/` 쓰레기가 생겼다. GUARDRAILS 의 worktree cwd 규칙([pipeline-worktree-cwd.md](pipeline-worktree-cwd.md))이
`pipeline.py` 만이 아니라 **모든 상대경로 명령**에 해당한다는 걸 확인했다 — 절대경로로 고정하거나
매번 `cd <절대경로> && ...` 한 줄로 실행한다.
